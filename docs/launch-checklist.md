# Чекліст запуску: реліз сайту + перша реклама

Покрокова інструкція від поточного стану (код готовий, нічого не налаштовано)
до працюючої реклами із заявками в таблиці.

Загальний час — близько години, з яких половина припадає на очікування
модерації Meta.

## Чому саме такий порядок

Кроки залежать один від одного, тож переставляти їх не можна:

```
Крок 1 (Apps Script) ─┐
                      ├─→ Крок 3 (змінні) → Крок 4 (деплой) → Крок 5 (перевірка)
Крок 2 (піксель)    ─┘                                              │
                                                                    ↓
                                    Крок 6 (прев'ю) ← ─ ─ ─ ─ ─ ─ ─ ┤
                                                                    ↓
                                                          Крок 8 (реклама)
```

Крок 7 (скриншоти) не блокує нічого — його можна зробити коли завгодно,
хоч і після запуску.

**Головне правило на весь документ:** усі змінні `NEXT_PUBLIC_*` вшиваються в код
під час збірки. Змінили значення в Netlify — **потрібен новий деплой**, самого
перезапуску недостатньо.

---

## Крок 1. Заявки в Google Таблицю (~15 хв)

Без цього форма не працює: людина заповнює поля, натискає кнопку і бачить
«не вдалося надіслати». Це найважливіший крок із усіх.

### 1.1. Створіть таблицю

Нова Google Таблиця → перейменуйте аркуш на **`Ліди`** (назва важлива, скрипт
шукає саме її). У перший рядок вставте заголовки — рівно в цьому порядку:

```
sentAt | form | name | contact | niche | utm_source | utm_medium | utm_campaign | utm_content | utm_term | fbclid | referrer | page
```

### 1.2. Вставте скрипт

У таблиці: **Extensions → Apps Script**. Видаліть увесь код, що там є, і вставте
готовий скрипт із [leads-apps-script.md](leads-apps-script.md), розділ 2.

Угорі скрипта замініть `ЗАМІНІТЬ_НА_СВІЙ_РЯДОК` на будь-який вигаданий рядок,
наприклад `limiter-2026-x9f2`. **Запишіть його** — знадобиться на кроці 3.

### 1.3. Опублікуйте

**Deploy → New deployment**, тип **Web app**:

- Execute as: **Me**
- Who has access: **Anyone**

Google попросить дозволи — погодьтесь. Він покаже попередження «Google hasn't
verified this app»: це нормально для власного скрипта, натисніть **Advanced →
Go to (назва проєкту)**.

Скопіюйте URL виду `https://script.google.com/macros/s/AKfy.../exec`.
**Запишіть його** — це `NEXT_PUBLIC_LEADS_ENDPOINT`.

> Якщо змінюватимете скрипт пізніше — щоразу робіть **New deployment**, а не
> «Manage deployments». Інакше URL лишиться старим, а зміни не застосуються.

### 1.4. Перевірте одразу

Не чекайте деплою сайту. Вставте в термінал, підставивши свій URL і секрет:

```bash
curl -s -X POST 'ВАШ_URL_APPS_SCRIPT' \
  -H 'Content-Type: text/plain;charset=utf-8' \
  -d '{"secret":"ВАШ_СЕКРЕТ","name":"Тест","contact":"@test","form":"curl"}'
```

У таблиці має з'явитись рядок, на пошту — лист. Якщо рядка немає — перевірте
назву аркуша (`Ліди`) і що секрет у команді збігається зі скриптом.

## Крок 2. Facebook Pixel (~10 хв)

Без пікселя реклама крутиться наосліп: Meta не знає, які покази дали заявки,
і не може оптимізувати покази під людей, схожих на ваших клієнтів.

1. Відкрийте **Meta Events Manager** (business.facebook.com/events_manager).
2. **Connect data source → Web → Meta Pixel**, дайте назву («Limiter studio»).
3. Коли запитає спосіб підключення — оберіть встановлення вручну
   (**Install code manually**). Сам код вставляти **не треба**, він уже в сайті;
   вам потрібен лише номер.
4. Скопіюйте **Pixel ID** — це число з 15–16 цифр. Запишіть його.

> Назви пунктів у Meta змінюються кілька разів на рік. Орієнтуйтесь на суть:
> вам потрібно створити піксель і дізнатись його числовий ID.

## Крок 3. Змінні в Netlify (~5 хв)

Відкрийте свій сайт на Netlify → **Site configuration → Environment variables**
і додайте п'ять змінних:

| Змінна | Значення |
|---|---|
| `NEXT_PUBLIC_SITE_URL` | `https://limiter-studio.netlify.app` |
| `NEXT_PUBLIC_LEADS_ENDPOINT` | URL Apps Script із кроку 1.3 |
| `NEXT_PUBLIC_LEADS_SECRET` | секретний рядок із кроку 1.2 |
| `NEXT_PUBLIC_FB_PIXEL_ID` | ID пікселя з кроку 2 |
| `NEXT_PUBLIC_GA_ID` | необов'язково, формат `G-XXXXXXXXXX` |

Якщо хочете спершу перевірити локально — створіть у корені проєкту файл
`.env.local` за зразком `.env.local.example` і запустіть `npm run dev`.
Файл `.env.local` у `.gitignore`, у репозиторій він не потрапить.

## Крок 4. Деплой (~5 хв)

Netlify збирає сайт із гілки `main` репозиторію `pog-nazar/limiter-studio`,
тож деплой — це просто пуш.

```bash
npm run lint && npm run build   # переконатись, що все збирається локально
git add -A
git commit -m "feat: посадкова під рекламу, форма заявок, підготовка до релізу"
git push origin main
```

У Netlify відкрийте **Deploys** і дочекайтесь статусу **Published** — зазвичай
1–2 хвилини.

> Якщо збірка впаде з помилкою про змінні — перевірте, що всі п'ять зі кроку 3
> збережені **до** пушу. Netlify підставляє їх на етапі збірки.

---

## Крок 5. Перевірка після деплою (~10 хв)

Пройдіться по списку на бойовому сайті. Найкраще — **з телефону**, бо саме
звідти прийде майже весь рекламний трафік.

**Сторінки відкриваються:**
- `/` — головна
- `/lp/` — посадкова
- `/privacy/` — політика
- `/robots.txt` і `/sitemap.xml` — віддають текст
- будь-яка вигадана адреса — україномовна 404

**Форма (найважливіше):**
1. Відкрийте `/lp/`, заповніть форму, **зачекайте щонайменше 3 секунди** перед
   натисканням — швидше спрацює антибот і ви побачите помилку.
2. Має з'явитись зелений блок «Прийнято ✦».
3. У таблиці — новий рядок. У колонці `form` буде `hero`, `order` або `popup`
   залежно від того, яку форму заповнили.
4. Спробуйте надіслати ще раз одразу — має бути відмова з проханням зачекати
   хвилину. Це очікувано.

**Піксель:**
Встановіть розширення **Meta Pixel Helper** для Chrome. На `/lp/` воно має
показати подію `PageView`, а після відправки форми — **`Lead`**. Якщо `Lead`
не з'являється, реклама не зможе оптимізуватись під заявки.

Паралельно в Events Manager → **Test Events** видно ті самі події в реальному часі.

## Крок 6. Прев'ю посилань (~5 хв)

Перевіряти можна тільки на живому сайті — локально це не оцінити.

1. Відкрийте **Facebook Sharing Debugger**
   (developers.facebook.com/tools/debug/).
2. Вставте `https://limiter-studio.netlify.app/lp/` → **Debug**.
3. Має з'явитись темна картинка 1200×630 із заголовком «Сайт, який приносить
   заявки — за 3–5 днів».
4. Повторіть для головної — там картинка «Сайти, що продають».

Якщо картинки немає, а замість неї помилка про тип файлу — значить не
застосувались заголовки з `netlify.toml`. Перевірте, що файл є в корені
репозиторію і деплой пройшов після його додавання.

> Facebook кешує прев'ю надовго. Змінили картинку — тисніть **Scrape Again**
> у Debugger, інакше побачите стару.

## Крок 7. Скриншоти проєктів (можна пізніше)

Зараз кейси показують стилізовану заглушку з назвою. Виглядає навмисно, але
справжні скриншоти помітно піднімають довіру.

1. Відкрийте проєкт, зробіть скриншот десктопної версії без панелей браузера.
2. Обріжте до пропорції **16:10**, оптимально **1600×1000 px**.
3. Стисніть у **WebP** через squoosh.app, цільова вага — **до 150 КБ**.
   Це важливо: у конфізі стоїть `images.unoptimized`, тож віддається рівно той
   файл, який покладете.
4. Покладіть у `public/images/`.
5. У `src/data/projects.ts` додайте рядок у потрібний проєкт:

```ts
{
  id: "massage-website",
  title: "Serenity Salon",
  image: "/images/serenity.webp",   // ← цей рядок
  liveUrl: "https://...",
}
```

Заглушка зникне сама, скриншот з'явиться і на головній, і на `/lp`.
Можна додавати по одному — у кого `image` немає, той і далі показує заглушку.

## Крок 8. Запуск реклами

### 8.1. Створіть кампанію

У Ads Manager: нова кампанія, ціль — **Ліди** (Leads), місце конверсії —
**Вебсайт**.

На рівні групи оголошень:
- **Подія конверсії: `Lead`** — та сама, що спрацьовує при відправці форми
- Гео: ваше місто або область
- Вік: 25–55, стать — усі
- Інтереси: краще **не звужувати** на старті. Алгоритм Meta знаходить
  аудиторію сам, якщо бачить конверсії

### 8.2. Адреса посадкової

```
https://limiter-studio.netlify.app/lp/
```

Саме `/lp/`, не головна. Слеш у кінці обов'язковий.

### 8.3. UTM-мітки

У полі **URL parameters** оголошення вставте:

```
utm_source=facebook&utm_medium=paid&utm_campaign={{campaign.name}}&utm_content={{ad.name}}&utm_term={{adset.name}}
```

Meta підставить назви автоматично, а сайт запише їх у таблицю разом із заявкою.
Саме за цими колонками ви побачите, яке оголошення дало клієнта, а яке — злило
бюджет.

### 8.4. Чого очікувати

Перші кілька днів Meta «вчиться» — заявки можуть бути дорогими й нерівномірними.
Алгоритму потрібно близько **50 конверсій на тиждень** на групу оголошень, щоб
вийти на стабільну роботу. Не вимикайте кампанію через два дні тиші й не міняйте
налаштування щодня — кожна правка перезапускає навчання.

Якщо заявок немає взагалі за 3–4 дні при нормальних показах — проблема
найімовірніше не в рекламі, а на сторінці. Дивіться в GA, до якої секції люди
доходять і де закривають.

## Що ще варто зробити найближчим часом

Не блокує запуск, але варто:

- **Свій домен** замість `.netlify.app` — у рекламі власний домен виглядає
  надійніше. Після покупки достатньо змінити `NEXT_PUBLIC_SITE_URL` і зробити
  новий деплой, код не чіпається.
- **Перечитати політику конфіденційності** (`/privacy/`) — вона написана як
  шаблон. Якщо оформите ФОП, туди треба додати реквізити.
- **Оновити версію Next** — `npm audit` показує вразливості в `sharp`
  (залежність Next). На статичний сайт це не впливає, бо `sharp` працює лише
  під час збірки, але тримати оновленим варто.
